# XTTS + SILMA F5 Voice Studio — تحديث معالجة الصوت والنص

واجهة FastAPI لمعالجة عينات المتحدث وتوليد الكلام باستخدام محركين قابلين للاختيار:

- **XTTS-v2**: المحرك الافتراضي متعدد اللغات، ويظل مناسباً عند الحاجة إلى اللغات التي لا يغطيها محرك F5 المثبت.
- **SILMA TTS المبني على F5**: اختياري، ويدعم العربية والإنجليزية وفق نسخة SILMA المثبتة. يتطلب نص العينة المرجعية.
- **Auto / Ensemble**: موجودان في الواجهة الحالية؛ يختار Auto حسب توفر SILMA والنص المرجعي واللغة. الوضع المزدوج ينتج مرشحين مستقلين، ولا يحوّل خرج أحد المحركين إلى صوت الآخر.

## المعالجة المضافة

1. `app/audio_processing.py`: يحول العينة إلى mono/22.05 kHz، يخفض الضوضاء المستقرة بمرشح FFmpeg `afftdn`، يقص الصمت الأطول من ثانية تقريباً، ويطبق تطبيع EBU R128 إلى -23 LUFS. إذا لم يدعم إصدار FFmpeg مرشح خفض الضوضاء، يعيد المحاولة من دون هذا المرشح.
2. `app/text_processing.py`: يزيل الروابط والرموز التعبيرية، يوحّد المسافات والترقيم، ويوسّع الأرقام والعملات المدعومة عند توفر `num2words`.
3. بعد التوليد، يطبق مرشحات EQ خفيفة وتطبيعاً إلى -18 LUFS قبل إرجاع الملف.

**حدود مهمة:** `afftdn` خفض ضوضاء تقليدي وليس إزالة صدى/انعكاس غرفة حقيقية. إزالة الصدى عالية الجودة تحتاج نموذجاً متخصصاً مثل DeepFilterNet أو أداة dereverb، ولم تُجعل اعتماداً إلزامياً حتى لا تثقل تثبيت CPU ولا توحي بقدرة غير موجودة. كذلك لا يُنشأ التشكيل العربي آلياً: التشكيل التخَميني قد يغيّر معنى الكلمات؛ التشكيل الموجود في النص يُحافَظ عليه. تحويل الأرقام إلى كلمات ليس بديلاً عن مراجعة النصوص الحساسة أو الأعداد ذات السياق الملتبس.

**لا يمكن ضمان تطابق صوتي تام مع منصات تجارية**؛ جودة الاستنساخ تتأثر بجودة العينة، والنص المرجعي لمحرك F5، واللغة، وإصدار النموذج والعتاد. استخدم أصواتاً لديك إذن صريح باستعمالها.

## المتطلبات والتشغيل

يتطلب المشروع Python 3.12 وFFmpeg. تثبيت CPU:

```bash
chmod +x setup_cpu.sh run_cpu.sh
./setup_cpu.sh
./run_cpu.sh
```

لإضافة SILMA/F5:

```bash
./setup_f5.sh
```

اعتمادية معالجة النص الجديدة هي `num2words>=0.5.14,<1`. بقية معالجة الصوت تعتمد على FFmpeg المثبت في النظام ولا تحتاج حزمة Python إضافية. `silma-tts` اختياري بحسب ملف المتطلبات/طريقة التثبيت.

## ملاحظات الأداء والإعداد

- تشغيل CPU على 4 vCPU وذاكرة 16 GB ممكن لكنه أبطأ من GPU، ومرشحات FFmpeg تضيف زمناً بسيطاً عند الرفع وبعد كل عملية توليد.
- `FAST` يخفض زمن إعداد مطابقة XTTS؛ و`high` يستخدم سياقاً مرجعياً أطول وقد يحسّن الثبات على حساب الوقت.
- يمكن تعيين `FORCE_CPU=0` لاستخدام CUDA عند توفرها، و`CPU_THREADS` لضبط خيوط CPU.
- معاملات `temperature`, `top_p`, و`repetition_penalty` تطبق على XTTS عبر واجهته الحالية. لا تُمرر هذه المعاملات إلى `SilmaTTS.infer` لأن واجهة SILMA المتاحة في المشروع لا تعرضها كمدخلات موثقة.
- قد تختلف نتيجة `loudnorm` قليلاً عن الهدف النظري في المقاطع القصيرة جداً؛ وهو تطبيع مستوى إدراكي وليس تطبيع قمة فقط.
